# Implementation

## Trigger and inputs
Use only after Issue, contract, Reviewer Checklist, and required design are approved. Read current Issue phase, branch/HEAD, affected components, project profile, `document_impact`, explicit doc owners, and diff.

## Procedure
1. Run `python -m agent_workflow agent-context <issue>` and verify the approved Contract before using it. Read the normalized `workspace.isolation` policy.
2. For `auto` or `required`, reuse the host-managed worktree already bound to this execution. Otherwise ask the active host surface to create or enter one before edits: Claude Code uses native `EnterWorktree` with deterministic name `issue-<issue>`; Codex uses its managed worktree or task-fork capability when exposed. The parent Codex task may coordinate while the isolated task writes. Never shell out to `codex` or `claude`, or run raw automatic `git worktree add`.
3. If host isolation is unavailable, `auto` continues in the current checkout; `required` stops before edits. `disabled` does not request a new worktree and does not force a session already in a worktree back to the main checkout. Antigravity and other unverified hosts use the current-checkout path for `auto` and block for `required`.
4. In the current-checkout path, run `python -m agent_workflow start-feature-branch <issue> <issue title> [--base-ref <branch>] [--expected-base-sha <sha>]` and record its returned base and branch. In an isolated path, retain the host-owned local branch or detached HEAD and record the selected base SHA.
5. Run `python -m agent_workflow prepare-implementation <issue> --mode isolated|current [--base-ref <branch>] [--expected-base-sha <sha>]` using the actual workspace mode and selected base. Do not edit source until the binding succeeds.
6. Confirm workspace, branch publication identity, and scope; change specifications first if a material requirement changes. Implement the smallest complete behavior, then add focused tests with fake GitHub boundaries.
7. Re-evaluate all three Document impact decisions against the final diff; update the Issue rows if the spec, design, or status choice changed. Validate declared owners with `python -m agent_workflow validate-docs --issue <issue>`. Run configured hooks in declared order and record skipped targets as unverified.
8. Preserve any approved Issue-scoped target release exactly through the handoff; do not derive or substitute a version. Include the target selection and contracted milestone command/result in delivery evidence when milestone assignment is part of the contract. Save checkpoints/evidence and request triage for category-C discoveries.
9. Run the Issue-routed `verify_quick` hook, then commit only the approved Issue-scoped changes; continue without another conversational prompt by running `python -m agent_workflow ensure-review-pr <issue> --body-file <path>`. Pass the exact selected `base_ref` with `--base-ref` for stacked work. An isolated binding publishes to its frozen canonical branch while retaining the host-owned local branch.
10. At the resulting exact PR HEAD, run `python -m agent_workflow verify-final <issue> <pr>`, prepare/validate/publish the exact-HEAD self-review, and follow the [QA Skill](../qa/SKILL.md). Then hand the PR to a new session/subagent or human using the [PR review Skill](../pr-review/SKILL.md). The implementation execution must not author that independent-review artifact. If no independent reviewer is available, keep the delivery gate blocked and report the PR URL and blocker. Run `python -m agent_workflow delivery-check <issue> <pr>` only after all four evidence records exist; read Required Checks from its result.
11. Ordinary follow-up answers and corrections reuse the same binding/workspace; do not allocate a new worktree. After Contract supersession, run `prepare-implementation --supersede` in the same execution before continuing. After any new PR commit or approved contract/checklist change, regenerate affected HEAD- or contract-bound evidence and rerun the delivery gate. Do not report implementation complete until an open, non-draft review PR exists, all evidence gates pass, and Required Checks succeed.

## Output and uncertainty
Report changed paths, commit/push/PR state, exact-HEAD Verification/QA/self-review evidence, independent-review status, Required Check state, unverified checks, and delivery result. Approval of the contract execution authorizes the routine handoff operations above; do not ask for a separate PR-creation approval. Stop on contract conflict that requires a new decision; never broaden unknown scope or infer application type. See the [application profile index](../../standards/application-profiles/README.md).
